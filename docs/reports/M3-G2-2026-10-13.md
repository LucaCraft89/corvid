## Private AI / blind-sign (ipprotection-ppissuer) reachability

Traced in the source of the Azure tree (inference from code, not from a run):
- `kPrivateAi` is `FEATURE_ENABLED_BY_DEFAULT` (`components/private_ai/features.cc:12`), but `PrivateAiServiceFactory::BuildServiceInstanceForBrowserContext` returns nothing unless `PrivateAiService::CanPrivateAiBeEnabled(channel)` (`components/private_ai/private_ai_service.cc:35-38`) is true, which needs a non-empty API key.
- `GetApiKey` (`:26-32`) takes the key from the feature param `api-key` (default empty, set only through a variations seed or a command-line field-trial param) or from the Google Chrome API key only if `IsGoogleChromeAPIKeyUsed()`. Our args set empty `google_api_key` and `use_official_google_api_keys = false`; the variations seed fetch is off (0110). So by default no service object exists and nothing contacts the issuer. The service also needs a signed-in account, and sign-in is disabled (0130).
- It can be switched on only by a user passing `--enable-features=PrivateAi:api-key/...`. Smallest cut if wanted: make `CanPrivateAiBeEnabled` return false (one early return in `private_ai_service.cc`), a one-line patch. Not written; the user decides whether defence in depth is worth a patch.

## New finding: Web Speech cloud endpoint

`libcontent.so` holds `https://www.google.com/speech-api/full-duplex/v1/down?` (and `.../up?`). That is Chromium's cloud speech recognition endpoint, used when a page calls `webkitSpeechRecognition` (microphone audio would go to Google). `www.google.com` is on the binary allowlist (search provider), so the gate does not see it. Reachable only on a page action plus a microphone permission, not at idle. Not traced to the source file. Recommend a small patch to disable the cloud speech service or point it to `.invalid`; needs Luca's decision (it also removes a working feature). The allowlist entry `www.google.com` is therefore broader than its stated reason.
