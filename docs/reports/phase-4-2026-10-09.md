# Phase 4 report: self-hosted E2EE sync (2026-10-09)

Platform in scope: Linux build sandbox, Go 1.26 (auto-fetched toolchain), Node 22. No Chromium tree, no Windows host, no Docker daemon.
Overall: **server, client engine and `corvid://sync` page are built and their locally runnable acceptance tests pass. Phase 4 is NOT complete**: the threat model is a draft awaiting sign-off, nothing is integrated into Chromium, and Linux+Windows real-client convergence and the container build are unverified.

Reproduce: `tests/acceptance/phase-4/run.sh` (exit code 0 on the run below; race detector on; 30 s native fuzz).

Bugs found by the tests and fixed during the run: mux redirect returned HTML for `..` paths (now 400 JSON); OPAQUE wrong-passphrase attempts are invisible to the server so lockout counts every `login/start` per (user, IP); tombstone compaction left deleted records alive on stale clients (client now reconciles on resync); recovery could un-revoke a device id (now refused).

## Not done / unverified
- Windows + Linux real-client convergence: UNVERIFIED. No Chromium integration (C++ port or sidecar undecided; Mojo bridge stub; `patches/series.phase4` is empty with planned hook patches listed).
- `Dockerfile` / `compose.yaml` / `Caddyfile`: written, NOT built or run (no Docker daemon). The server binary itself was run (`/v1/info`, `-healthcheck` OK).
- Postgres: not implemented (SQLite only).
- History and open-tabs sync: not implemented (user decision pending).
- OPAQUE state for in-flight logins is in memory: single instance only.
- No external security review. OPAQUE library is not independently audited.
- Recovering a client after restoring an OLD server backup (re-trust after rollback) is not implemented.
- Passphrase strength policy is not enforced anywhere yet.
