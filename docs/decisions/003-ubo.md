# 003: uBlock Origin (phase 6, 2026-10-31)

Read from `imputnet/helium-chromium` rev 2 `58261a2` (`patches/helium/core/ublock-*.patch`, `helium/ui/ublock-show-in-settings.patch`, `deps.ini`), the `imputnet/uBlock` and `gorhill/uBlock` 1.75.0 release files (diffed), and `gorhill/uBlock` HEAD `af21fe5` (`dist/chromium/update.xml`).

## What Helium ships

- **A fork:** `imputnet/uBlock` 1.75.0 (`deps.ini`, sha256 `49214674…`). Against upstream 1.75.0 it changes 17 files: Helium filter lists (annoyances, unbreak) added and on by default, CNAME uncloaking through a new `chrome.dns` API that Helium adds to the browser (`ublock-dns-uncloaking.patch`, 551 lines touching `net/dns`), a default-list migration, an about page naming the fork. Bundled filter lists are newer snapshots.
- **Built into the binary** as a component extension (`blockjmkbacgjkknlgpkjjiijinjdanf`, 4.5 MB in `ublock_resources.pak`), with every remote list address stripped from `assets.json`. Component extensions cannot update; Helium special-cases this id in about 15 places so it can be disabled and run in private windows.
- **Updates:** the extension only with the browser. Filter lists only through Helium's own server (`/ubo/assets.json`, imput's proxy), and only after the user agrees to Helium services in onboarding; otherwise never.
- **Credits:** `third_party/ublock/README.chromium` (says version 1.66.4, ships 1.75.0).

## What PROJECT.md asks

uBlock Origin "bundled unmodified as a separate extension", preinstalled, enabled by default, updatable, credited (GPL-3.0, source link). Helium's fork is none of these except preinstalled and enabled.

## Facts that decide it

- The Chrome Web Store no longer serves uBlock Origin (MV2): its update service answers `noupdate` for `cjpalhdlnbpafiamejdnhcphjbkeiagm`.
- Edge Add-ons still serves it (`odfafepnkmbhccpbejgmiehpchacaeak`, 1.75.0 repacked by Microsoft as version `2026.916.75.0`, served over plain HTTP).
- The authors publish their own signed Chromium build: every GitHub release has `uBlock0_<v>.chromium.crx` (id `fkgkibajhfbepljeaefdnfnegdcjomkh`), and `dist/chromium/update.xml` in the repository is a working update manifest for it (stable channel at 1.75.0 as of today).
- Upstream uBO reads admin settings from `chrome.storage.managed` (documented, used by enterprises). That is configuration, not a code change.

## Decision (taken)

Ship **upstream uBlock Origin, unmodified**: the authors' signed 1.75.0 `.crx`, checked against a pinned sha256, id and version at build time (`build/ublock.conf`, `build/ublock.sh`), installed into new profiles from `<install dir>/extensions/` as a normal extension. The user can disable or remove it like any other; once removed it is not reinstalled.

- **Updates:** from the authors' own channel: the update address inside their signed package (1.75.0: `cdn.jsdelivr.net/gh/gorhill/uBlock@master/dist/chromium/update.xml`, a mirror of `dist/chromium/update.xml`; the raw GitHub file is the fallback if a package names none), new packages from `github.com` release assets. Off by default, one switch in `corvid://preferences` ("Keep uBlock Origin up to date"). While off, the browser never checks for a new version and uBO's own list updater is held off through managed storage (`userSettings: autoUpdate=false`); uBO runs on the lists inside the package, which are refreshed with every Corvid release. Reason: the privacy gate (zero connections at idle, allowlist starts empty, hosts only with the owner's approval) and uBO's default list updater starting 37 s after launch would conflict.
- **Helium's fork:** not loaded (one line in `component_loader.cc`), its 4.5 MB pak not packed, its README marked not shipped. Its special cases stay in Helium's patches, dead but harmless.
- **Credits:** `third_party/ublock_origin/README.chromium` (GPL-3.0, upstream URL, licence text taken from the package).

## What we lose against Helium's fork

- CNAME uncloaking (needs Helium's `chrome.dns` API and the fork's code; upstream only does it on Firefox).
- Helium's annoyance and unbreak lists (users can add them by URL in uBO).
- Filter lists through a proxy: when updates are on, uBO fetches lists from the list hosts directly, as on any other browser.

## Open for the owner
