# UI stage 1 for 0.1: the smallest safe shell (2026-10-14, written without the tree)

Goal (Luca: "all features including UI?"): the UI in 0.1 must look and feel like Corvid and be customizable where it is cheap, while staying a stable daily driver. The full custom WebUI chrome (M5: WebUI tab strip/toolbar, free layout) is NOT safe for Thursday: it replaces tab strip, omnibox, focus, drag-to-reorder, IME, accessibility and extension toolbar behavior (docs/notes/chrome-shell-approach.md). Stage 1 therefore keeps Chromium's native window and changes only what is low-risk. Fallback at every step: the stock-UI build (stage 1 patches are independent; any failing one is dropped from `patches/series`, the rest still apply).

## What stage 1 contains
| # | Patch (new, `ui/`) | What | Risk | Needs grep first |
|---|---|---|---|---|
| U1 | `ui/0240-default-theme-seed` | Chromium builds an autogenerated theme from a seed color (user "Customize Chrome > color" feature) and has a color-scheme/contrast model. Set Corvid's default seed (DESIGN.md `#5B6BC0`) when the profile has no theme, and feed our theme engine's seed into the same API so the native toolbar/tabs take Material-3 tonal colors. No new UI | low | `rg -n "BuildAutogeneratedThemeFromColor\|autogenerated" chrome/browser/themes`, `ThemeService::SetAutogeneratedTheme`, pref `kBrowserColorScheme`/`kUserColor` names |
| U2 | `ui/0250-corvid-side-panel-entries` | Register Corvid panels (starting with one: corvid://sidebar placeholder for modules) in the native side panel registry, so Corvid WebUI panels live in Chromium's own side panel host | low-medium | `rg -n "SidePanelRegistry\|SidePanelEntry::Key\|SidePanelEntryId" chrome/browser/ui/views/side_panel \| head`; how entries are registered per browser (`SidePanelUtil::PopulateGlobalEntries`) |
| U3 | `ui/0260-vertical-tabs-default-off-user-on` | Only if the pinned tree has Chromium's own vertical tab strip: expose it in `corvid://settings` as an option (default horizontal). If absent: dropped, vertical tabs deferred to M5 | low | `rg -n "kVerticalTabs\|VerticalTabStrip\|vertical_tab" chrome/browser/ui chrome/browser/ui/views/frame \| head` |
| U4 | `ui/0270-hide-stock-menu-items` | Route/hide stock menu entries that open stock screens (already blocked by ui/0220 at the URL level; this removes the dead menu items like "Google Lens", "Chrome Web Store" promos, "Reading mode" if it needs Google) | low | app menu model: `rg -n "AppMenuModel::Build\|IDC_" chrome/browser/ui/toolbar/app_menu_model.cc \| head` |

Explicitly NOT in stage 1: address bar at the bottom (no native support), free layout editing of the chrome, WebUI tab strip, WebUI toolbar. They stay in the layout engine and `corvid://settings` as modules/panels only.

## Why this is the smallest safe set
- U1 is data/default only: no layout, focus or input code is touched.
- U2/U3 reuse Chromium-owned containers, so keyboard, a11y and window management stay native.
- Each patch is independently droppable; the series has no ordering dependency between them.

## Prioritised compile and test list for the VM thread (order matters)
1. **G4 overlay pieces 1 to 5** (already specified in docs/notes/g4-spec.md; `corvid_phase1_unittests`, filters in the spec). Cheapest: overlay-only, minutes per cycle. Report compile errors back by file.
2. **Apply G3 (0300, 0320, 0330) + branding render, build `chrome`**, run acceptance 06/07/08 and the rename test (`CORVID_REUSE_BUILD=1`). This is the build the release hangs on.
3. **Idle capture + 01b on that same build** (privacy gate; hard gate for any release).
4. **Wire diagnostics (patch 2001 + NavigationErrorCollector/HangCollector)**: only after (1) compiles; tiny patch, then rerun (2)'s sanity (browser starts, opens a page, no crash).
5. **U1** (theme seed): quickest visible UI win; verify manually: new profile shows tonal blue-violet chrome, light/dark follow system.
6. **U2, U3, U4** in that order, each followed by "browser starts and a 5-minute browsing sanity" before moving on. Drop any that fails; do not debug at the cost of the release.
7. **Package** (`scripts/package.sh`) from the build in (2)/(4)/(5): label honestly as debug smoke-test unless a release build was run.
8. **Passkeys** adapter after `docs/notes/fido-api-155.md` exists.

## Stability gate before calling anything "0.1"
Browser starts and runs a 30-minute browsing session without crash on the packaged build; extensions page works; uBO blocks on the test page; idle capture clean; settings/new tab/history/downloads open as Corvid pages. Anything not run is SKIPPED in the report, not passed.
