# Stock `chrome://` pages: status

Task 1.8. Every stock Chromium WebUI page is either **replaced** by a Corvid page, **redirected** to one, or **blocked** (shows `corvid://blocked`). The source of truth is `ui/pages/stock-pages.json`; the table below and `src-overlay/corvid/webui/stock_page_table.inc` are generated by `node ui/tools/gen-stock-pages.mjs` (CI runs it with `--check`).

**Status of this list: UNVERIFIED.** The host list was reconstructed from memory of `chrome://chrome-urls` for a recent Chromium, because no Chromium checkout was available. The acceptance script `tests/acceptance/phase-1/02-no-stock-screens.mjs` enumerates the hosts from the real built browser and fails on any host missing from this table, so gaps are caught at the first real build.

Other schemes handled by the same policy: `chrome-untrusted://`, `chrome-search://`, and the `chrome-error://` error container (Corvid error pages replace the stock interstitials; see `ui/pages/error`).

Open points:
- DevTools (`devtools://`, the DevTools frontend) is a stock UI. Assumed kept as a developer tool; Phase 2 adds `devtools-extension`. Needs a user confirmation (listed in the Phase 1 report).
- Diagnostic pages (`net-internals`, `webrtc-internals`, `tracing`, ...) are blocked until the Phase 2 diagnostics hub provides equivalents.
